[ ] P2. A1 - REGROUP THE FOLDS BY PATIENT (GroupKFold on SUBJECT_ID)
        Effort: hours.  Impact: largest single correction available.
        "None of this is worth measuring until the fold leakage is fixed."

        Why: folds split on HADM_ID, but 129 admissions come from only 100 patients
        (one patient has 15). 41 of 129 test cases (31.8%) have another admission from
        the same SUBJECT_ID sitting in their own retrieval pool. Per-fold contamination
        15%-54%. Measured inflation at threshold 1.0: +0.11 to +0.26, against encoder
        differences of only 0.015-0.046 and per-fold sigma of 0.071-0.124.
        THE CONTAMINATION IS ~10x THE EFFECT UNDER STUDY.

        Tell: on leaked cases all three encoders score IDENTICALLY (0.293 MAX,
        0.415 TOP-10); on clean cases they diverge (0.080 / 0.114 / 0.125).

        Affects BOTH arms - the fold files are shared static artifacts, so the
        published 0.489/0.512/0.521 carry the leakage too.

        This is a data regeneration, not a code change (folds are committed files).

        TRAP: cython_utils.py:202 does line[line.index("_")+1 : len(line)-1] and drops
        the last character unconditionally. ANY regenerated fold file MUST end with a
        trailing newline or the last symptom of the last line loses a character.
        (Docs citing :184 are stale - the package move shifted it.)

          {HADM_ID}_{raw SYMPTOMS field verbatim}.\n    <- note the APPENDED PERIOD
        Files live at data/folds/Fold{0..9}/{TrainingSet,TestSet}.txt (116/13 lines,

[ ] P4. A2 - REPLACE THE COSINE GRADER WITH A DRG-BASED ONE
        Effort: days.  Impact: makes cross-encoder comparison valid AT ALL.

        Why: the same encoder both RETRIEVES and JUDGES. The grader is
        get_diagnosis_similarity_by_description_max (cython_utils.py:315), which reads
        the SAME embedding dict used for retrieval. Called from cython_utils.py:126
        and :151 (baseline) and bert_models.py:509 (BERT) - so ALL FOUR ARMS
        SELF-GRADE, not just the transformers.

        A more compressed embedding space grades itself more leniently, "which is
        exactly why BiomedBERT, the most compressed of the three, 'wins' at threshold
        0.9" - 99.71% of its patient pairs clear 0.9 regardless of whether the
        diagnosis is right.

        Enabler: the DIAGNOSIS field already carries DRG group names. String
        comparison needs no embedding.

        *** PARTIAL HEAD START IN THE REPO - BUT NOT USABLE AS WRITTEN ***
        Two encoder-independent graders already exist, ZERO CALLERS:
          cython_utils.py:353  get_diagnosis_similarity_baseline
                               graded - fraction of true diagnoses matched
          cython_utils.py:365  get_diagnosis_similarity_by_drgcode
                               binary  - 1 if any true diagnosis was predicted
        DO NOT let P17's dead-code sweep delete them; they look dead only because
        nothing calls them yet.

        CORRECTED 2026-08-05 - an earlier version of this file called these a
        ready-made head start. They are NOT. Four independent failure modes:
          1. They compare the "apr,ms:" PREFIX as part of the string. `c in list`
             is exact whole-string equality. The real grader at :315 strips the
             prefix first (:321, :323); these two do not. So "hcfa:septicemia
             age >17" and "apr,hcfa:septicemia age >17" - the same DRG - miss.
          2. Prefix ORDER is hash-order nondeterministic. It is built by iterating
             list(set(...)) at :291/:305-307, so "apr,hcfa:foo" vs "hcfa,apr:foo"
             varies BETWEEN PROCESSES. A string-equality grader is therefore
             nondeterministic. PYTHONHASHSEED is not actually pinned.
          3. The prefix is a DRG *type* label (apr/hcfa/ms = three coding systems),
             NOT a DRG code. There is no numeric DRG code anywhere in the data -
             only description text. Cross-system exact matching essentially never
             fires: "Intracranial Hemorrhage" vs "INTRACRANIAL HEMORRHAGE OR
             CEREBRAL INFARCTION" for the same admission.
          4. Prefix reconstruction is itself buggy - `if x in d` at :306 is
             SUBSTRING containment, so "sepsis" inherits hcfa from "hcfa:severe
             sepsis", and description "a" inherits hcfa because "a" is inside the
             literal word "hcfa". Pinned at test_characterize_preprocessing.py:231-273.
        Also: get_diagnosis_similarity_baseline divides by len(gt_diagnosis) with
        no zero guard (:362).
        Still the right starting point. Budget real work, not a one-liner.

        DO NOT use exact match alone - see the 58.1% ceiling. Use graded relevance:
        full credit for an exact DRG match, partial for a same-family match.

[ ] P5. B1 - RANK-AWARE RETRIEVAL METRICS (Option C: Recall@K, MRR, nDCG)
        Effort: days.  Depends on P4 (needs the encoder-independent relevance label).
        The ONLY option that fixes all three metric defects at once.

        Why: rank IS computed at bert_models.py:170 and then DISCARDED. The scorer
        (containGreaterOrEqualsValue, cython_utils.py:366-370) returns true if ANY of
        the K candidates clears threshold, so a hit at rank 1 and a hit at rank 50
        count identically. That makes score(TOP-50) >= score(TOP-10) true BY
        CONSTRUCTION - verified monotonic in 18/18 model x threshold combinations,
        zero violations. The TOP-K curve in the README is arithmetic, not a finding.

        Bonus: rank-aware metrics are SCALE-FREE, so they are immune to both the
        saturation problem and the per-model calibration problem.

[ ] P6. B2 - SET-LEVEL SOFT PRECISION / RECALL / F1 (Option B)
        Makes precision and recall genuinely independent quantities that can trade
        off, which KILLS THE DEGENERACY. Does not fix the self-grading or rank defects.
            soft_precision = mean over predicted p of ( max over true g of cos(g,p) )
            soft_recall    = mean over true g      of ( max over predicted p of cos(g,p) )
            soft_f1        = harmonic mean of the two

[ ] P7. A4a - "w/o" COLLAPSES TO "w"; NEGATION IS DESTROYED
        preprocess_sentence (cython_utils.py:251-260) pads "/" so "w/o" becomes
        ["w","/","o"]; "/" is dropped as punctuation and "o" IS AN NLTK ENGLISH
        STOPWORD. Verified: "Tracheostomy w/o Extensive Procedure" and
        "Tracheostomy w Extensive Procedure" BOTH become
        "tracheostomy w extensive procedure".
        Fix: protect "w/o" before slash-padding, or drop "o" from the stopword set.
        MUST BE ITS OWN COMMIT - it moves every number.

[ ] P8. A4b - COMMA-SPLIT FRAGMENTS
        Symptoms are ","-split but ICD-9 short titles contain commas, so 80 of 1,805
        tokens (4.4%) are orphan fragments. " organism NOS" appears in 26 admissions;
        because similarity is mean-of-max, any two of those get a spurious 1.0
        contribution from a token carrying no clinical content. Severity distinctions
        also collapse (stage I vs stage IV).
        Fix is deterministic, no model needed: every fragment begins with a leading
        space (the separator is "," while intra-label commas are ", "), so if a token
        starts with a space, rejoin it to the previous token.
        Verified to recover all 80: 573 -> 564 unique symptom strings.

[ ] P9. B5 - KEEP THE LEGACY NUMBER
        Report the existing MAX-at-0.6 result alongside everything new, clearly
        labelled as legacy, so results stay comparable to Comito et al. and to this
        project's own history. Keep every metric SIDE BY SIDE rather than replacing.

[ ] P10. A5 - CENTRE THE EMBEDDINGS BEFORE COMPUTING COSINE
        Effort: ONE LINE.  Impact: unknown, worth measuring.
        BERT embeddings are anisotropic (Ethayarajh 2019) - a documented property of
        the MODELS, not of MIMIC-III. Demo with random vectors: a shared offset moves
        mean pairwise cosine from 0.001 to 0.94, reproducing the three models'
        measured similarity profiles with no medical content whatsoever.
        Fix: subtract the mean embedding (the core of BERT-whitening). If it works, a
        single shared threshold becomes meaningful again.
        NOT THE SAME as normalize_embeddings=False at bert_models.py:337-343, which
        cannot affect results at all - L2-normalising before a cosine that already
        divides by the norms is algebraically a no-op.

[ ] P11. B4 - PER-MODEL THRESHOLD CALIBRATION (Option D)
        Set each threshold at a fixed PERCENTILE of that model's own similarity
        distribution instead of a hardcoded 0.6. Equal-selectivity values from the
        measured medians: BiomedBERT ~0.93, Bio_ClinicalBERT ~0.84, BlueBERT ~0.72.
        A patch, not a fix - makes cross-model comparison meaningful without
        addressing leniency or rank.

[ ] P12. B3 - MEAN INSTEAD OF MAX (Option A)
        Cheap. Fixes only the leniency defect. New problem: dilution - a patient with
        3 true diagnoses and 1 correct prediction averages the correct match against
        2 irrelevant comparisons, so patients with more diagnoses are penalised for
        having more diagnoses. Worth having as a registered aggregator, not an end state.


===============================================================================
THE 58.1% CEILING - READ BEFORE DESIGNING ANY EXACT-MATCH METRIC
===============================================================================
The method predicts by copying an answer from a retrieved patient, so the answer must
EXIST in the pool to be copied. 145 unique diagnosis descriptions across 129
admissions; 105 of them (72.4%) occur exactly once in the whole dataset.
Only 75 of 129 test cases (58.1%) have their correct DRG present anywhere in their
fold's training pool. The other 41.9% are unwinnable under exact matching - not
because retrieval is bad, but because the answer is not in the library.
A PERFECT RETRIEVER THEREFORE CAPS AT 58.1% UNDER EXACT MATCH.

Three ways to handle it, in order of preference:
  1. Graded relevance - partial credit for a same-family DRG. Raises the ceiling and
     is more clinically sensible than all-or-nothing.
  2. Report against the ceiling - "X of a possible 58.1%". Honest and standard.
  3. Restrict evaluation to the 75 winnable cases and say so. Cleanest signal,
     smallest n.

NOTE: measured on the CURRENT, LEAKY folds. Re-measure after P2. Neither plan says so.
